# 짭짤한 공기 (GEOSINT)

| 항목 | 값 |
|---|---|
| 카테고리 | OSINT / GEOSINT |
| 난이도 | 쉬움 (입문용) |
| 배점 | 100 (권장) |
| 플래그 | `hacklipse{비스타블루베이커리카페}` |
| 배포 파일 | `dist/cafe.png` |

## 디렉터리

```
geosint-salty-air/
├── README.md          # 이 파일 (출제자용)
├── description.md     # 플랫폼에 붙여넣을 문제 설명문
├── challenge.yml      # CTFd(ctfcli) 등록용
├── solution.md        # 풀이 (배포 금지)
├── salty-air.zip      # ★ 업로드용 압축본 (cafe.png 1개만 포함)
├── dist/
│   └── cafe.png       # ★ 참가자 배포본 (메타데이터 제거 완료)
└── src/
    └── 비스타블루베이커리카페.png   # ★ 원본 (절대 배포 금지 — 파일명이 정답)
```

## 배포본

| 파일 | SHA-256 |
|---|---|
| `salty-air.zip` | `491e6f98abb42f9ed6f8a72f337b3725ad481b71b666dc3d0d36c9e246a8ac52` |
| `cafe.png` | `6508de931631f0a85283d5adc30bce697445e20bbf175ce92681b32ed07748ce` |

`salty-air.zip` 안에는 `cafe.png` **한 개만** 들어 있다. `src/`(파일명이 정답),
`solution.md`, `README.md`, `challenge.yml`은 모두 제외됨. `zip -X`로 압축해서
uid/gid·확장 속성도 남기지 않았고, 아카이브 바이트 전체에서 `비스타/vista/blue/
snipaste/screenshot` 문자열이 검출되지 않는 것까지 확인했다.

재생성:
```bash
cd dist && zip -X -9 ../salty-air.zip cafe.png
```

## 출제 시 적용한 처리

1. **파일명 변경** — 원본 파일명 `비스타블루베이커리카페.png`가 정답 그 자체였음.
   배포본은 `cafe.png`로 변경. (다른 이름을 쓰려면 `IMG_4821.png`처럼 무의미한 것으로)
2. **메타데이터 제거** — 원본에 있던 PNG `tEXt` 청크 2개
   (`Software=Snipaste`, `User Comment=Screenshot`)를 삭제.
   스크린샷 도구 흔적이 남아 있으면 "원본 사진이 어딘가에 있다"는 사실이 바로 노출됨.
   GPS/EXIF는 원래부터 없음 → 의도대로 **순수 이미지 분석 문제**가 됨.
3. **플래그 형식 명시** — 상호명 문제는 띄어쓰기/표기 분쟁이 100% 발생하므로
   "지도 앱 등록 정식 상호 / 띄어쓰기 없이 / 한글" 규칙과 가짜 예시를 설명문에 박아둠.

## 테스트 방법

### 1단계 — 패키지 자동 검증 (즉시 가능)

```bash
cd geosint-salty-air
python3 -I verify.py
```

배포물에 정답이 새지 않는지(파일명·PNG 청크·zip 바이트·설명문), `challenge.yml`이
정합한지, 플래그 채점 정규식이 정답 변형 9종을 통과시키고 오답 7종을 거르는지 검사한다.
**플래그나 설명문을 수정할 때마다 다시 돌릴 것.**

### 2단계 — 풀이 가능성 검증 (사람이 직접, 가장 중요)

입문용 난이도의 핵심 경로가 리버스 이미지 서치이므로, **실제로 걸리는지 확인하지 않으면
난이도가 '쉬움'이 아니라 '불가능'이 된다.** `dist/cafe.png`를 아래 세 곳에 올려본다.

| 서비스 | 주소 | 기대 결과 |
|---|---|---|
| 구글 렌즈 | images.google.com → 카메라 아이콘 | 블로그 후기 글에 같은 장소 |
| 네이버 스마트렌즈 | 네이버 앱 → 렌즈 (한국 로컬에 가장 강함) | 플레이스 또는 블로그 매칭 |
| Yandex | yandex.com/images → 업로드 | 지형/건물 유사 이미지 |

- 셋 다 아무것도 안 나오면 → 예비 힌트(서해안)를 처음부터 공개하거나,
  해상도가 더 큰 원본으로 교체.
- 지도 앱 키워드 검색(`바다뷰 베이커리 카페`, `잔디 오션뷰 대형카페`)으로도
  몇 번째 결과에 나오는지 세어볼 것.

### 3단계 — 블라인드 테스터 (생략 금지)

**출제자 본인은 테스트할 수 없다.** 이미 답을 알기 때문에 체감 난이도가 항상 왜곡된다.
정답을 모르는 사람에게 `salty-air.zip` + `description.md` **딱 두 개만** 주고:

- [ ] 시간 측정 — 입문용 목표는 **10~20분**. 40분 넘으면 힌트 추가 또는 난이도 상향 표기.
- [ ] 어디서 막혔는지 기록 — 바다라는 걸 눈치챘는지, 리버스 서치를 떠올렸는지
- [ ] 플래그를 **처음에 어떤 형태로 제출하려 했는지** 메모 → 관대 채점 목록에 반영
- [ ] 엉뚱한 카페로 확신하고 간 적 있는지 (오답 유인이 너무 강하면 힌트 1 보강)

### 4단계 — CTFd 실제 등록 테스트 (선택)

로컬에 CTFd를 띄워 업로드·채점까지 확인:

```bash
docker run -d --name ctfd-test -p 8000:8000 ctfd/ctfd:latest
# http://localhost:8000 → 초기 설정 → Admin → Challenges → New
# 설명은 description.md 붙여넣기, 파일은 salty-air.zip 업로드,
# flag는 hacklipse{비스타블루베이커리카페} (+ 관대 채점분 추가)
docker rm -f ctfd-test     # 테스트 끝나면 정리
```

확인할 것: 한글 설명문이 깨지지 않는가, 첨부 다운로드가 되는가,
**관대 채점용 플래그를 추가했다면 CTFd에서 regex 타입으로 넣었는가.**

> `challenge.yml`의 `files:`는 현재 `dist/cafe.png`를 가리킨다.
> zip으로 배포할 거면 `salty-air.zip`으로 바꿀 것.

## 출제 전 체크리스트

- [ ] **리버스 이미지 서치로 실제로 풀리는지 확인.** 입문용 난이도의 핵심 경로다.
      구글 렌즈·네이버 스마트렌즈·Yandex에 `dist/cafe.png`를 올려서
      해당 카페 후기 글이 나오는지 직접 테스트할 것. 하나도 안 걸리면 난이도가
      '쉬움'이 아니라 '불가능'이 된다 → 예비 힌트(서해안) 공개 또는 지역 힌트 추가.
- [ ] **해상도 확인.** 현재 388×249로 매우 작다. 간판·메뉴판·차량 번호판 등
      읽을 수 있는 글자가 전혀 없어서 단서가 '지형 + 파라솔 + 잔디'뿐이다.
      더 큰 원본이 있으면 교체를 권장(특히 좌측 건물 형태가 또렷해지면 난이도가 적정해짐).
- [ ] **정식 상호 재확인.** 네이버 지도/카카오맵에서 실제 등록 상호가
      "비스타블루 베이커리카페"가 맞는지 확인하고 플래그를 최종 확정할 것.
      (상호가 바뀌었거나 폐업했으면 문제 자체가 성립하지 않음)
- [ ] **저작권.** 사진이 직접 찍은 것이 아니라 블로그/SNS에서 캡처한 것이라면
      공개 대회 배포 시 출처 표기 또는 본인 촬영 사진으로 교체 검토.
- [ ] **날짜 표현.** 설명문의 "작년 10월"은 2026년 기준 2025년 10월을 뜻한다.
      대회가 해를 넘겨 열리면 어긋나므로, 그런 경우 "재작년" 또는
      "2025년 10월"처럼 절대 날짜로 바꿀 것. (현재 플래그는 날짜와 무관하므로
      풀이 자체에는 영향 없음)
